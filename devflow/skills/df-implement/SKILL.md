# df-implement 实施

把获批设计落成代码；多步设计一次只实施一步，小步交付。

## 前置校验

1. 定位 design.md：参数路径优先，否则取 `docs/devflow/` 下最近修改的；没有则停止，提示先 `/df-design`。
2. 获批留痕：状态头改为 `状态: 已确认（YYYY-MM-DD，经 df-implement 调用批准）`。
3. 定步骤：参数指定（如 S2）→ 校验其依赖步骤已"完成"；无参数多步 → 取下一个未开始且依赖满足的步骤，确认后执行；单步 → 直接 S1。依赖不满足则停止说明缺口，不跳步。
4. design.md 仍有未决决策点：先请用户逐条拍板。

## 流程

1. 只做该步：读该步方案要点、验收标准与已采纳的 D 结论，不做相邻步骤的事。
2. 仓库有代码生成链路：先改源文件执行生成，再写业务代码；遵循仓库工程规范（AGENTS.md 等，如有）。
3. 每个可验证单元立即执行最小验证；跨模块/公共结构变更同步构建受影响模块。
4. 收口：对照该步验收标准逐条自检 + 仓库验证门禁（如有），汇报实际命令与 PASS/FAIL，禁止用一次全量构建充当唯一结论。
5. 该步完成：design.md 总览回写 `完成`，impl-log.md 追加该步小节，汇报（结论 → 改动点 → 验证证据 → 剩余风险）后停止，提示 `/df-review S<该步>`；用户明示继续才实施下一步。

## 协议变更

发现必须改已冻结协议：停止呈报，确认后改 design.md 的 S1 与协议版本记录，评估对已完成步骤的影响再继续。

## impl-log.md 模板（按步骤追加）

```markdown
# <change-id> 实施记录

状态: 进行中 | 完成 | 中断
上游: <design.md 路径>
日期: YYYY-MM-DD

## S1 <步骤名>

改动点：<文件 + 意图>
验证：<命令与 PASS/FAIL>
偏离：<无，或附用户确认方式>
```

## 硬性约束

- 偏离即停：需偏离设计（漏项、代码事实冲突）时呈报等用户决定，被接受后回写 design.md。
- 中断恢复：重入先按步骤总览与 impl-log 对账已完成改动并向用户呈现，再续作，不重做已完成项。
- 未经用户明确要求不执行 git commit/push；禁子模块 checkout/pull/reset。
- 代码生成产物只经其生成脚本更新，禁止手改。
- 语言跟随用户（默认中文）。
